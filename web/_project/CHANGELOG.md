## 2026-04-20 — Persistence boundary audit
### Stored in `quotesync.db`
- `clients` table stores client/business/contact/address/location data plus soft-delete marker.
- `estimates` table stores estimate refs, revision, status/outcome, defaults JSON, positions JSON, order meta JSON, project/location fields, timestamps, and soft-delete marker.
- Orders are not a separate table; they are estimates with `outcome = 'Order'` plus `order_meta_json`.
- `client_notes` and `estimate_notes` store one long-form note record per client / estimate.
- `notes` stores event-style notes linked to clients, estimates, and optionally follow-ups, including `created_by`.
- `followups` stores due-date workflow items linked to client and optionally estimate.
- `settings` stores grouped JSON settings and feature flags.

### Not stored in `quotesync.db`
- Estimate collection list/grid mode.
- My / All filter choice.
- Expanded estimate state (`expandedEstimateId` / `globalExpandedEstimateId`).
- Search / sort / month filter state.
- Client Files tab entries and document links currently remain frontend-only.

### Findings
- Current persistence boundary is broadly correct: business records are persisted; per-view UI state remains frontend-only.
- Lightweight user role foundation currently exists in code constants only and is not persisted in `quotesync.db`, which is acceptable for this phase.
- Ownership fields were added in server bootstrap and estimate route code (`created_by_user_id`, `created_by_name`, `created_by_role`), but the live `quotesync.db` schema inspected during audit does not yet show those columns. This means ownership persistence depends on the server bootstrap migration running successfully against the live DB before the boundary is fully real in storage.
- No separate files/documents persistence layer exists yet.
